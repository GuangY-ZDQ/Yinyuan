## 三、发现并修复的问题

| # | 现象 | 根因 | 处理 |
|---|---|---|---|
| 1 | 所有包都在"校验失败：外壳部分应在 X 处结束"挂掉（仅当壳视频尾部是 size=0 的盒） | size=0 盒按规范表示"延伸到文件末尾"，扫描器把后面追加的压缩包也算进这个盒，`parsed_to` 必然等于整个产物大小，而校验仍按"必须停在 prefix"判定 | 校验放行"`last_size_zero` 且 `parsed_to == 输出总大小"`的情况 |
| 2 | 输出路径与输入视频同名时，静默把源视频覆盖成产物（返回成功） | 没有做路径冲突检查，直接 rename 覆盖 | 引擎开头加同路径检测，明确报"输出文件不能和输入文件用同一个名字" |
| 3 | 传入 MKV / AVI / WMV / TS 时只报"盒结构在 0 处就断了" | 只做了通用失败文案 | 读文件头魔数区分类型，提示"这是 MKV / WebM 视频 / 这是 AVI 视频……请先转成 mp4" |
| 4 | 传入 7-Zip / WinRAR 的原生分卷时误报"很可能缺少某一片" | 未区分"字节切片式分卷"与"带盘标记的原生分卷" | 检测分卷首部 `PK\x07\x08` 标记，改提示"原生分卷格式不能靠拼接还原" |

另有两例是测试素材本身有误（同一路径被两个 zipfile 句柄同时写入，生成出损坏包），重新生成后通过，不属于程序缺陷。
