隐渊 1.0.0  —  使用说明（简版）        作者：泽渊
================================================

作用：把一个 ZIP 压缩包藏进一个仍然能正常播放的 MP4 里。
      输出文件后缀是 .mp4 时能正常播放；改名成 .zip 后能正常解压。

绿色单文件（约 3 MB，界面自带 MiSans 字体，别人电脑上不装字体也长一样），
免安装，不需要任何运行库，不写注册表。


一、三步操作
------------
1) ① 壳视频：选一个 .mp4（这就是别人看到的那个视频，.mov/.m4v 也接受）
2) ② 隐者：  选一个 .zip（带密码的 zip 也可以）；分卷包也直接选，选中任意一片即可
3) ③ 输出文件：留空就自动命名为「原名_隐.mp4」，与压缩包放在同一目录
             （多这个「_隐」后缀是为了不和你的原视频、原压缩包重名）
             换压缩包时会自动跟着换到新包的目录；你亲手改过这一格就不再自动覆盖
             也可以点「另存为…」自己挑位置和名字

点「开始合成」，或者在任意输入框里按回车。
完成后日志卡只显示三行：开始合成 / 合成成功（输出路径与文件大小）；失败时显示失败
原因。技术细节（盒结构、偏移、校验数据）不会显示，界面上也不需要看。

小技巧：也可以直接把文件拖进窗口——MP4 落到第 1 格，ZIP / .001 / .z01 落到第 2 格。

界面右下角有个「高级选项」，平时不用管；只有想省那 8 个字节时才需要展开。


二、输出文件会有多大
--------------------
输出大小 = 壳视频大小 + 压缩包大小（默认模式再多 8 字节）。
程序不对视频做任何转码，只是把视频字节原样复制一遍，再把压缩包接在后面。

所以：1 GB 视频 + 2 GB 压缩包 = 约 3 GB，不会变小。

体积关键不是分辨率，而是「码率 × 时长」：
    体积(MB) ≈ 码率(Mbps) × 时长(秒) ÷ 8

  640x360  400 kbps   1 分钟 3 MB / 10 分钟 30 MB / 1 小时 180 MB
  1280x720 1.5 Mbps   1 分钟 11 MB / 10 分钟 110 MB / 1 小时 675 MB
  1920x1080 5 Mbps    1 分钟 37 MB / 10 分钟 375 MB / 1 小时 2.2 GB

最省体积的做法：壳视频根本不用长。压缩数据藏在播放器会跳过的盒子里，
文件有 3 GB 也不会让视频播 3 小时。所以用一段 5～10 秒的 480p 小视频
（几百 KB）就够，此时输出 ≈ 压缩包本身的大小。

注意：FAT32 的 U 盘/移动硬盘单文件上限 4 GB。超过会直接报错，不会写坏文件。


三、怎么取出里面的压缩包
------------------------
把 xxx_隐.mp4 改名成 xxx_隐.zip，然后任选一种方式打开：

  Windows 资源管理器   直接双击
  WinRAR / Bandizip    直接双击解压
  7-Zip                直接拖进去；或用它的 # 号技巧（对 xxx.mp4# 操作）
  macOS                双击解压
  Linux                unzip xxx.zip
  手机                 ZArchiver 等解压 App

压缩包里的文件名、目录结构、压缩方式、密码全部原样保留。


四、分卷压缩包
--------------
  * 1.ZIP.001 / 1.ZIP.002 / ...   （7-Zip、好压、Bandizip 的默认分卷方式）
        -> 程序自动找齐同目录下的所有片、按序号拼好再合成。选第 001 片、还是
           第 005 片都行，产物完全一样。
        -> 前提：必须从 .001 开始、序号连续、所有片都在同一个文件夹里。
           只下到一半、或漏了第 1 片时，会明确提示「找不到分卷的第一片
           「名字.zip.001」」或「缺少第 N 片」，不会产出半成品。
  * xxx.z01 / xxx.z02 / xxx.zip  （WinRAR 的“跨盘式”分卷）
        -> 这种包每片里的偏移是按本片记录的，直接拼起来不是合法 ZIP，程序会
           明确提示，并建议用 7-Zip 以 .001 方式重新分卷，或先解压再打成一个 zip。
  * 只放了其中几片
        -> 提示「分卷不完整：缺少第 N 片」或「检测到 N 个分卷，但拼起来不是完整的 ZIP」。


五、「高级选项」里的“老式拼接”是什么
------------------------------------
默认不勾：
      在 MP4 末尾写一个合法的 free 盒，把 ZIP 装进这个盒里，同时把 ZIP 内部的
      所有偏移统一修正。MP4 结构合法、ZIP 偏移也合法，谁都能解。这是推荐方式。

勾上：
      不写 free 盒，直接把 ZIP 字节贴在视频后面。产物小 8 字节，WinRAR / 7-Zip
      照样能解，但资源管理器、unzip 这类严格读取器可能报错。
      除非你只打算自己用 WinRAR 解、并且真的在意那 8 个字节，否则不要勾。


六、命令行（在 cmd / PowerShell 里用）
--------------------------------------
  "隐渊.exe"                                          打开界面
  "隐渊.exe" -m 壳视频.mp4 -z 压缩包.zip -o 输出.mp4     合成
  "隐渊.exe" -m 壳视频.mp4 -z 1.ZIP.001 -o 输出.mp4      分卷也能直接传
  选项：-raw 老式拼接（等于勾上高级选项）   -q 静默   -h 帮助
  省略 -o 时自动命名「原名_隐.mp4」


七、注意事项
------------
* 支持：.mp4/.mov/.m4v 壳视频 + .zip 压缩包（含 ZIP64、加密 zip、300+ 条目）
        + 数字序号式分卷（.001/.002/...）
* 不支持：rar / 7z / 跨盘式分卷(.z01) / 空压缩包（0 个文件）
        ——会直接报错，不会产出坏文件
* 输出大小 = 壳视频 + 压缩包（默认模式多 8 字节）
* 目标盘若是 FAT32，单文件上限 4GB，会提示
* 程序只在你自己指定的位置写文件：先写 .part，回读校验通过才改名为正式文件，
  任何失败都会把 .part 删干净
* 部分杀软会对"单文件 exe + 读写磁盘"启发式误报，程序不联网、不写注册表、
  不装服务，可自行复核后加白
* 痕迹：程序只在你指定的输出位置写文件（先写 .part，校验通过再改名），
  不改注册表、不用系统临时目录、不写配置和日志、不联网、不往系统装字体
  唯一能避免的一点：点“浏览…”时 Windows 的文件对话框会记下这次访问的目录
  （系统行为）。若连这个都不想留，直接拖拽文件进窗口，或在输入框里粘贴
  完整路径即可（带不带引号都行）。
* 界面字体使用了 MiSans（小米免费商用字体）的子集，已内嵌在程序里。


验证产物是否完好（可选，需要 ffmpeg）：
  ffmpeg -v error -i 输出.mp4 -f null -
  没有任何输出 = 视频可以完整解码
【为什么改后缀后 Bandizip 能直接打开】
     产物里 ZIP 的偏移保持「相对」原值，解压器会按「文件末尾的目录位置」自己算出前面的视频有多大、
     再自动补偿。这是 Bandizip / WinRAR / 7-Zip / 系统自带解压都支持的方式。
【为什么每次生成的文件大小、哈希都不一样】
     产物在 ZIP 前面会随机垫 64~256 字节空白（在 free 盒内部），所以同样的视频+压缩包，每次生成的
     文件会差一百多字节。这样做是为了让「PK」签名不紧贴视频结构、降低被网盘或下载器按特征识别的概率，
     也不影响解压（解压器是从文件末尾找目录的）。

【解压用什么工具】
     Bandizip / WinRAR / 7-Zip 实测都可以直接打开（改后缀 .zip 后双击即可）。
     Windows 资源管理器自带的解压对这类「前面还有视频数据」的文件不一定认，建议用上面三个。
如果报「ZIP64 EOCD 记录签名不匹配」，说明压缩包前面带了附加数据或是 ZIP64 结构，本版已自动补偿；
